## As-built
core/async_region_source.gd: _wake_armed guarded by Mutex; false->true enqueue posts one wake; worker drains inner loop until queue empty, releases ownership under same lock. Camera set_generation removes pending/finished and counts them, in-flight completes but stale result discarded. close posts stop, joins, replaces Semaphore, clears counters/histograms. Worker admission includes pending+inflight+finished, no silent result drop. Main thread owns accepted count and cache. Existing public IO histogram maintained; new pipeline_profile exposes queue_wait, worker_service, delivery_wait, request_to_accept histograms. Opt-in captured per job, only accepted results included; cancellation metrics separate. Time stamps monotonic. Each accepted result updates all four; no percentile summation (different distributions).
Invariant at main-thread stats: submitted = accepted + cancelled_pending + cancelled_finished + cancelled_inflight + pending + inflight + finished. outstanding <= max_jobs. wake_cycles <= wake_posts before shutdown. Counters reset across reopen. No throughput claim without hardware.
preview exposes pipeline_profile. Profile JSON TF_PROFILE_2 includes pipeline, cancelled counters and outstanding at snapshot (before close), wake counters, resets extent on failed open. Existing accepted_worker_io_ms retained. No disk writes except explicit profiling fixtures/reports.

## Limits
GDScript worker still single. Full service includes file exists/open/read/hash/metadata/F32. No GPU timing, no measured battery impact. Stale work already in-flight can still block one read. Strict opening remains synchronous. Headless proof is correctness, not phone performance. Next P1.5.3a.
