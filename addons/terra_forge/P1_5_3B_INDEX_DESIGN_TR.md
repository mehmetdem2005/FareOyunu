## Decision
Use binary fixed-width indices instead of unbounded JSON parse. Keep TFR1 page layout, coordinate ownership and SHA. New opt-in format separate manifest.tfm2, old manifest.tfm remains untouched. No automatic migration or write/brush support. Start with codec only and isolated synthetic fixtures, then reader integration. P1.4 can later reuse immutable object/generation references; no generation publishing implemented here.

## Proposed binary contracts (freeze with tests before reader integration)
All little endian. Raw 32-byte SHA-256 digest, not hex strings. Root includes magic TFM2, version, dimensions (cells multiples of 32, 32..32768), Float32 spacing finite positive, page_width=32, shard_width=16, exact pages_x/z and shards_x/z derived, provenance tag and 32-byte digest. For genuine legacy source retain format+digest; synthetic fixture explicit distinct provenance + versioned generator descriptor digest (not TFH). Root entries row-major implicit shard coordinate, each 32-byte full shard SHA. Final 32-byte hash of entire header+entries. Header layout offsets reserved/zero validated and specified in codec docs. Max root 65x65=4225 entries at 32768² => 135200 entry bytes; header/checksum separate hard cap 256KiB. Reject truncated/extra bytes, wrong versions, invalid reserved fields, dimensions, zero/invalid digest policy, nonfinite spacing. No filename/path text from index.
Shard: magic TFS2, version, world dims/spacing, shard x/z, actual edge width/height derived (1..16), row-major implicit page hashes 32 bytes each, trailing payload digest. Max 256 entries =>8192 entry bytes plus header/checksum; hard cap 16KiB. Full-file SHA from pinned root checked before shard parse, internal SHA, header/coord and expected edge size validated. Path fixed from coords (s_%05d_%05d.tfs), page path existing r_%05d_%05d.tfr. Same immutable buffer for all checks. 4096 world 129x129 pages =>9x9 shards; 8192 257x257 =>17x17; 32768 1025x1025 =>65x65. TFM2 index capacity not proof of rendering huge map. At 8192² TFR1 payload+overhead ~264MiB logical and 66049 individual files; filesystem overhead is significant; packfiles future profiling decision.
 
## PR split
B1 codec: core/region_index_v2.gd (new), encode/decode root+shard, exact metadata validation, bounded length before buffer read, hash lookup by implicit ordinal. Tests small rectangular, corner/edge shards, theoretical max without generating 1M files, bad size/hash/magic/coordinates/reserved/spacing, wrong shard identity, corrupt page digest. Fuzz bounded mutated buffers. No production reader changes.
B2 scratch exporter: bounded generation by shard, explicit synthetic provenance, staged dir verified, cancel/space/preflight, real small multi-shard world; optional 4096/8192 benchmark not each push. Strict scans all shards/pages and verifies exact completeness; lazy root-only and requested shard+page hash. No mixed legacy root formats accepted silently.
B3 async reader: new opt-in open path, root bytes pinned, shard LRU cap (e.g. 4–16) separate from page cache; worker owns shard reads or worker-local cache, no mutable main scene references; job includes pinned root shard SHA and expected metadata. Admission counts pending+inflight+finished; camera epoch separate from snapshot identity. Result validated before cache acceptance, errors fail closed. Root hash/reader ID protects generation. Old TFM1 defaults same. Compare strict/lazy parity, nearest mesh/physics, cross-shard edge normals, corrupt shard and cold page, cancellation/close, memory budget.
B4 profile: add 4096/8192 options only when real supported generator+reader, explicit storage warning. Root bytes/shard bytes and resident counts, shard hit/miss, latency separately, compare same trace. Actual device test required. No claimed gain before measurements.
