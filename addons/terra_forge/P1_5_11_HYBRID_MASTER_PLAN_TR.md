## 1 — Architecture rules and non-negotiable invariants
1. Source authority immutable snapshot + session serial + epoch + key + LOD + seam signature + job ID; camera epoch != data generation. Worker never mutate SceneTree, Resource/RID or reader LRU from its own thread. Owned bounded immutable numeric payloads only; B tile view cannot outlive reader pin/session; no zero-copy claim without ownership proof.
2. One canonical geometry definition: same vertices, indices, normals, UVs, collision samples/triangulation, border orientation, world spacing and transforms. A reference and mathematical fixtures. No fake heights, dropping corrupted data or weakening parity; unsupported result fail-closed. If a path cannot be equivalent, keep it experimental, not I.
3. Physics authority separate from visual readiness. Current support leases non-evictable within explicit caps; changed-height coarse seam must have new verified shape and real physics confirmation, same-height may reuse. Guard before movement, never remove existing support to make room for optional jobs. If capacity insufficient deny movement safely with reason and recover; no freeze gravity or pretend raycast success. Visual LOD never determines multiplayer authoritative physics.
4. State model REQUESTED -> WAIT_PAGES -> READY_INPUT -> QUEUED -> RUNNING -> READY_RESULT -> VALIDATED -> PUBLISH -> RESIDENT; terminal FAILED/CANCELLED/SUPERSEDED with exact ownership release once. No unbounded staging. Pending+running+ready slots <= configured cap; preview reservations reconcile; verify latest signature again immediately before publish.
5. Budgets are explicit in units and scope: source payload bytes, slot counts, main-thread wall time, observed frame interval, optional publication count, resident pages/shards/tiles. GPU and native memory unknown stay null. A single API call can overrun; never promise hard frame deadline.
6. Stable defaults, one feature flag per hypothesis, one switch to disable I, no automatic backend switching mid-job, no silent strategy/quality changes. Disable optional jobs before reducing visual distance; never degrade safety. Reject invalid combinations at session start. Revert with ordinary commit/PR, not force push. Preserve failed raw evidence.
7. Existing P1.4R immutable writer architecture stays separate. Add snapshot boundary compatibility, not a writer in this phase. Preserve original TFH/TFL and all game assets.

### P1.5.11a1 — Publication micro-profile (independent telemetry lane)
Split _publish_geometry: describe/validate (outside current publish timer), node allocation, root add, visual/physics/collision attach, mesh array creation and assignment separately, shape init/map_data/assign, old resource release, seam/signature, bookkeeping. Capture _sync/eviction/IO poll/publish/submit/prune and full pump boundaries including pre-budget work. Event ID/tile/lod/new-vs-reuse/snapshot/bytes/frame/physics tick; top K slow events >= threshold, histogram and sample counts, timer overhead calibration; correlate spikes with frame intervals, no claim causation. Track total vs stage residual and unknown wall-time. Main/worker clock monotonic; thread CPU time if available else null.
Benefit: identify 128ms residual and repeated 90ms spikes. Cost: timer calls, locks, object allocation and log overhead. Gate: observation off parity, bounded diagnostic payload and <=5% median overhead in equal work, no per-frame giant log. No pooling before data identifies likely bottleneck.

### P1.5.11b — Common geometry contracts and halo parity
b0. Factor shared immutable JobInput/JobResult fields without rewrite of verified algorithms. All paths obey exact shape and visual contract, error codes and ownership. A/B/C/E/F/G/H remain accessible; avoid abstraction in per-vertex hot loops.
b1. Expand existing cropped halo to G with independent toggle; check scalar seam accesses against Dense.sample_bounds and required_pages; H separately. All cardinal/corner combinations, absent/same/coarse neighbors, world edges. No out-of-bounds fallback. b2 separate camera-only E/F halo toggle; existing motion logic unchanged. Ensure missing pages not silently ignored. b3 same applied halo to F/G/H and compare equal work; no assumption more cropping always beneficial (neighbor change can force rebuild).
Benefit: fewer page loads and input copies, common comparisons. Cost: branch/metadata, cache variants, potential seam/normal errors, rebuilds on neighbor changes. Gate: exact parity 48+ cases, both formats and real ray parity; no extra terrain gaps; reads/worker cost paired, not combined with unrelated optimization. Rollback: full halo per path.

### P1.5.11c — Backend selection (I-v0, F-equivalent first)
c0. Add explicit I option without changing default; exact F-equivalent implementation at first (flags, behavior, serialized mode validation). Reuse single worker; no second reader, no new thread pool. I parity including failure cases and all existing F tests.
c1. Dense vector path vs scalar path per LOD and seam signature, equal tile inputs. Measure build/copy/queue/delivery separately and peak scratch; use actual Android. Do not assume G wins because fewer vector allocations. c2. Topology cache independently on/off with same scalar setting, immutable templates, output copied if required. No GPU buffer sharing assumption. Measure startup cost, amortization count and repeated cold/reopen, track 32256-byte existing templates. c3. Compare B-view vs owned dense construction only on owner thread; if using page spans/pins, enforce pin cap and avoid LRU starvation; copy to owned payload before worker. No reader access on worker.
c4. Static per-device/per-LOD policy from repeated evidence, choose F baseline when uncertain; no online learning initially. Later opt-in dynamic switch only at job boundary, bounded samples, hysteresis and minimum dwell, never oscillate due to temperature. Unknown devices conservative F-equivalent I or A fallback according to explicit release policy. No benchmarking hidden in gameplay startup.
Benefit: combine genuinely faster backends. Cost: per-job metadata, dispatch, cache memory, first-run overhead, more test permutations and maintenance. Gate: exact parity, no more allocated worker slots, >=10% intended improvement or reject feature. F remains independently available.

### P1.5.11d — Work identity, cancellation, reuse and fairness
d0. Separate logical job identity (snapshot/key/lod/geometry signature) from camera epoch. Audit whether broad epoch pruning discards still-valid output; only preserve if identity and source pin exactly match at publication. Do not drop epoch validation wholesale. Distinguish necessary invalidation vs avoidable drops vs duplicate work.
d1. Stage cancellation token with bounded checks at row/stage boundaries (not every vertex), atomically release ownership. Gated tests cancel before copy, queued, in-flight row, complete, just before publish; stop/reopen and rapid reversal. No locks around long compute; avoid busy waiting; count actual wasted work time and cancellation overhead.
d2. Dedup/coalesce identical requests, keep at most one active per identity; priority changes not rebuild. Bounded ready queue, keep valid critical result, optional age promotion only when no critical reservation violated. cap1 special case; starvation under infinite critical demand explicitly cannot guarantee optional deadline, report age and recovery.
d3. Reuse exact geometry result cache only if justified: bounded small LRU by bytes, snapshot invalidation, count transient doubles; do not cache entire world. Prefer avoid needless rebuild over retaining heavy mesh arrays. Separate topology, heights, normals and collision signature keys.
Benefit: lower discarded CPU (F 47/297, 35 ready prunes), reduced latency. Cost: cancellation checks, locks, cache memory, complicated lifetimes; keeping stale-but-valid result demands rigorous signatures. Gate: ownership equality after each phase, no stale publish even adversarial timing, optional bounded recovery after finite burst, reduced dropped compute milliseconds not just fewer drop counters.

### P1.5.11e — Resource publication and bounded node pool
e0. Use micro-profile evidence first. Compare detached subtree construction (one attach), precreate inert slots gradually outside critical path, vs current node creation. Main thread only, no physics/RenderingServer calls in worker. e1. Bounded pool: FREE -> PREPARING -> ACTIVE -> RETIRING -> FREE. Idle root detached or collision disabled and no shape/mesh references; don't move active collision. On reuse clear shape, mesh, material overrides, transform, owner, signals/metadata, generation; verify no stale ray hit old or new position until ready. Physics-safe retirement after engine sync; never recycle current support. Live+reserved+idle and transient double allocations explicit; pool max8 empty slots initially, disabled fallback.
e2. Split publication if evidence warrants: validate owned result, allocate resource, stage visual, commit collision/visual revision at safe boundary. Keep old verified mesh/shape until replacement valid; cannot expose new visual seam with incompatible physical shape. Distinguish render lag and physics activation. No unbounded READY results, count staged slots in worker/memory ledger. Oversize one-item exception remains visible. No hard deadline claim because native call indivisible.
e3. Test frame budget policy with explicit soft wall deadline and per-pump byte/count, integrate existing publication accounting instead of duplicate budgets. Reserve critical progress; prevent optional oversize starving critical. e4. Investigate reusable mesh buffers/region updates only after engine API capability and exact parity; old and new resource lifetime/driver synchronization tested, source bytes not VRAM. Reuse only stable topology; no partial physics mismatch.
Benefit: reduce creation/free churn and worst-frame spikes. Costs: idle memory, transient duplicates, startup warm-up, reference leaks, ghost collision, staged latency. Gate: 1000+ bounded reuse cycles in synthetic test, current support never recycled, old locations no hit, changed-height seams and stop/reopen, measured p99/max and resource caps. Reject pool if spikes remain or memory cost outweighs gains.

### P1.5.11f — Reader delivery and predictive prefetch
f0. Measure queue/service/delivery for matched job IDs, accepted/dropped/cancelled accounting. F current IO delivery wait dominates mean; avoid interpreting physical disk from accepted reads. Profile main-thread poll timing and result readiness. f1. Reorder bounded poll relative to pump/physics tick; try early acceptance at deterministic point, one owner, no duplicate polling or hidden extra work. Avoid more frequent polling if mutex overhead/wakes/frame time worsen.
f2. Critical predicted footprint, adaptive horizon based on measured end-to-end readiness quantiles + speed and turning; bounded corridor, cap-aware, hysteresis, avoid prefetch behind after reversal; direction uncertainty conservative. Limit optional IO so required pages resident; no page pin without capacity plan. Cold shard cross boundary cap1 stress. f3. Explore page batching/coalescing of adjacent requests only if measured; format unchanged, hash each required page, don't let batch block critical. f4. Add true coverage readiness latency from request to physics-ready, not shape attachment; visual camera may run ahead without unsafe player movement.
Benefit: less wait, redundant read and denied movement. Cost: more memory, IO bursts, prediction errors, CPU wake/poll overhead, starving distant work. Gate: paired reads, actual readiness, all 36 motion cases, large/low-cache/teleport/corruption, no frame regression. Do not add background CPU simply to improve polling metric.

### P1.5.11g — LOD incremental geometry / stable topology (high risk, later)

Use canonical neighbor influence footprint. g1. same LOD and canonical heights, compare partial normal/edge recomputation with full output across all neighbors. HeightMapShape3D full replacement may remain necessary; do not promise partial GPU or physics upload. g3. evaluate interior/edge separate meshes or buffer update only if draw calls/seams/extra nodes do not outweigh savings; visual seam exact, index orientation parity.
Benefit: fewer full rebuilds and CPU allocations. Cost: bookkeeping, memory, more draw calls if split, full upload still possible, complex corner effects, stale normal/shape risk. Gate: compare full A generation every mutation/transition; actual ray tests; repeated LOD toggles and high slopes; reject if no measured win. Keep full rebuild fallback.

## 4 — Parallel lane discipline and execution queue
Immediate lanes (max3): A=deterministic publication test; B=telemetry micro-profile; C=report/export diagnostics. A and B share publication files: A owns test/accounting policy only, B owns observation instrumentation, coordinate contract or sequence overlapping changes. C independent tools branch, not gameplay branch. First merge exact verified A, B diagnostics only, C package independently. Then b halo parity; d0 identity audit can run in parallel as read-only design; no simultaneous worker implementation c/d to avoid overlapping changes. e pool depends on measured b? no: depends a1 evidence + stable publication contracts. f after identity/caps. g high-risk only after e/f, can be parked. h after stable metrics. i combined after accepted changes. Every new branch named by phase, no force pushes; docs updates batched to avoid cancellation of CI.
Definition of done per task: changed files, exact behavior, test coverage incl negative, CI log summary, metric deltas (or explicitly no metric), costs, decision, rollback, next small action. No new feature while a safety regression remains open. Don't make the user test every commit: CI first, targeted APK/Godot project only once a meaningful batch of measured candidates is ready.

## 5 — Cost/risk register
R01 CPU/GPU tradeoff: faster streaming may draw more triangles and increase GPU load; separate coverage, triangles, frame/GPU timing; no GPU claim. R02 memory: dense, cache, pool and staging accumulate; ledger and bounded caps, low memory fallback. R03 CPU/thermal: more workers, frequent polls and logging heat phone; one worker default, measure long run and energy if possible. R04 latency: budget defers results, prefetch wrong direction, staged publication; track real-ready latency and denied ticks. R05 correctness: stale snapshots, seams, ghost collisions; exact identity, canonical A, ray and capsule tests. R06 maintenance: many combinations; explicit features, backend policy, bounded matrix, remove rejected features from I only, retain reference branches. R07 measurement: clock/scheduler, debug overhead, unequal work; deterministic gate, paired repeated tests, raw evidence and unknowns. R08 storage: report size, scratch data and future writer; bounded log/export, no real data write; P1.4R separate. R09 fairness: infinite critical load may starve optional; reserve critical slots, quantify age/recovery, no unsafe deadline promise. R10 quality: adaptive far reduction may make comparison misleading; equal-quality mode, report actual LOD coverage. R11 portability: Mali driver/Android permissions vs Linux headless; no native assumptions, device gate. R12 schedule/scope: do not indefinitely chase stretch FPS; finite closure and parked optimization list, P1.4R scratch return. R13 cancellation/resource reclamation: stale in-flight ownership, double free, references from rendering/physics; exact state transitions, no deletion before safe retirement. R14 fallback: A may cost more main-thread CPU; fallback only explicit session-safe mode, not silent midframe; fail closed if data corrupt.
