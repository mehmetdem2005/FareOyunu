- add/remove default p_update true calls update_maps(TYPE_MAX,true,false) and instancer update_mmis. update_maps clears/free RIDs, rebuilds region index and emits region_map_changed, rebuilds all 3 layered textures, recalculates height range, emits maps_changed, snaps terrain. terrain_3d.cpp region_map_changed connected to collision build (destroys/recreates body & pool), height_maps_changed to AABB update, maps_changed to material region array uniforms. Empty native asset list can enable checker.
- https://github.com/TokisanGames/Terrain3D/blob/v1.1.0-stable/src/generated_texture.cpp : create(layers) calls RenderingServer.texture_2d_layered_create; update(image, layer) calls texture_2d_update. update_maps individual edited region update only when no full rebuild and no other map change. - https://github.com/TokisanGames/Terrain3D/blob/v1.1.0-stable/src/terrain_3d_region.h : RF height/control, RGBA8 color; sanitize_map creates missing maps and generates color mipmaps. terrain_3d.h defaults COMPRESS_NONE, keep_uncompressed_color true.
- https://github.com/TokisanGames/Terrain3D/blob/v1.1.0-stable/src/terrain_3d_collision.cpp : dynamic grid pool updates when snapped location changes, independent of render LOD; region_map_changed invokes build.

## Hesap (ölçüm değil)
64 * 512^2 * 4 bytes = 64 MiB for each height/control base; RGBA8 full mip chain = 64 * 4 * (512^2 + 256^2 + ... + 1) bytes = 85.33325 MiB. Total logical payload 213.33325 MiB, per region ~3.3333 MiB, excluding overhead; no height/control mips assumed per native standard maps. CPU images retained and GPU arrays created; naive two logical representations total ~426.67 MiB, NOT an actual memory reading or guaranteed extra physical allocation (unified memory, driver staging, allocation policy, compression, copies, etc.). 63-layer rebuild ~210 MiB logical payload, vs ~3.33 MiB one layer update. Actual elapsed CPU/GPU wait and resident memory not measured. 60 FPS budget 16.67 ms. No claim about bandwidth or time.

## Seçilen strateji
1. Dört Havza V2 64 region loaded once, all resident, current visual LOD & native dynamic collision; no camera-triggered add/remove, no background workers, no duplicate terrain mesh.
2. P1.7.2 stable coordinate -> immutable descriptor index, only manifest metadata, no redundant image copies; P1.7.3 budget based on actual device capacity and logical CPU/GPU payload separately, no guessed RAM thresholds.
3. P1.7.4–8 conditional: async read/decode only if demonstrated need; fixed cap, dedup/cancel, one or fewer workers as appropriate, backpressure, no work when resident world fits. Prefetch/cache/hysteresis may be unnecessary with resident world. Do not build speculative systems just to tick boxes.
4. For larger worlds investigate stable GPU slots + per-layer update through native extension, atomic indirection/neighbor guards, physical ground priority and distant silhouette. Requires isolated native branch, compatible mobile binaries, safe read-only eviction API, validation of slot replacement and collision notifications, bounded memory, old/new generation lifetime, real device timings. No assumption upstream GDScript API alone supports safe slot streaming.
5. Alternatives: naive add/remove rejected due full array + collision rebuild + retained deleted resources; multiple Terrain3D instances not default (seams, duplicate GPU/physics/materials); smaller regions not default (count and shader map capacity, no inherent lower total memory, visual seams risk); offline partitions at explicit world transition only if needed. Keep full near quality, no silent draw distance reduction.
6. P1.7.9 ground pinning and P1.7.10 distant terrain only as needed and proven. Current world has no streaming; no runtime mutation this audit.
