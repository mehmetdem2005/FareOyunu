# P1.8.4 — Horizon culling fizibilitesi (27 Kasım 2026)
Kaynaklar: https://docs.godotengine.org/en/stable/tutorials/3d/occlusion_culling.html ; https://docs.godotengine.org/en/stable/classes/class_occluderinstance3d.html ; https://github.com/TokisanGames/Terrain3D/blob/v1.1.0-stable/src/terrain_3d_mesher.cpp ; src/terrain_3d.cpp aynı tag.
Godot occlusion culling CPU Embree düşük çözünürlükte occluder rasterizes; occludee AABB bütünüyle kapalı olmalı. Native clipmap RID instance meshes shared by many tiles and LODs; update_aabbs global height range (conservative, not local tile range); height_maps_changed updates AABBs. Shader-displaced flat grids, moving clipmap target, edit brush changes, holes, negative heights and morph footprint complicate safe occluder construction. No per-ring instance visibility API in current GDScript bindings; blanket hide terrain/whole LOD incorrect. Existing renderer frustum and depth testing retained; depth rejection not identical to skipping submission.
Rejected for now: extra CPU raymarch per frame, duplicated terrain occluder mesh, per-frame BVH rebuild, coarse height sampling treated as guaranteed visibility, GPU readback stalls, arbitrary global cull margin reduction. No code added to runtime for horizon culling. Native future candidate: conservative tile bounds from edit-invalidated min/max hierarchy; account morph start/end+neighbor footprint, near edit protection, holes, use conservative occluder lower bounds and occludee upper bounds; stable camera positions, fail open for uncertainty, no blocking GPU readback, measure end-to-end cost. Do not make this a prerequisite for every terrain. P1.8.4 feasibility closed, implementation deferred, no measured improvement.
